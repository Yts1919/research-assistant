# 分节写作 (section-writing)

## 核心：先论证、后成文

1. **一句话论证**：动笔前用一句话锁定——「在[问题]中，我们用[方法]证明了[进展]，证据是[证据]，边界是[边界]」。写出的每一段都要服务于这句话。
2. **确认要点**：起草前先向用户复述「本节要论证什么 + 用哪些证据」，确认后再写。

## 工作流

1. 首次写作先初始化草稿：`python tools/section.py --init "论文标题" --out 草稿.json`；
2. 每写一节，把「本节一句话论证 + 草稿」存进草稿 JSON，并写入右侧「写作」面板：
   - 草稿 JSON 结构：`{"title":"…","argument":"整体论证","sections":[{"id":"引言","argument":"…","results":["结果1","结果2","结果3"],"final":"…"},…]}`；
   - 写入面板：`python tools/paper.py --write-card --panel <config.section_json_path> --card 草稿.json`；
3. **结果1 由 AI 生成**：用户只填「一句话论证」，你（AI）据此生成结果1 的正文草稿填入 `results[0]`；结果2/结果3 作为备选版本（可让 AI 再生成不同风格/精简版，或用户自己在面板里编辑）；
4. **AI 智能融合**：当用户要把某节的多个版本融合成一个时，融合由你（AI）完成——把选中的版本去重、保留关键信息、统一语气，写出最终结果，填入该节 `final` 字段；
5. **符号/术语台账**：每节末尾把新引入的符号、术语登记到 `ledger`，下一节起草前先查台账；
6. 全部写完**拼接全文**（按各节 final）：`python tools/section.py --concat 草稿.json --out paper.md`。

## 与悬浮窗的交互

- 「写作」面板是可编辑的：用户可在面板里直接改论证/各版本/最终结果，编辑保存在浏览器 localStorage；
- 面板「AI融合(复制给AI)」按钮会把选中的版本复制到剪贴板，用户粘贴到对话发给你，你融合后写回该节 final；
- 面板「简单合并」是浏览器端的机械拼接（不调用 AI）；
- 面板「导出全文」按各节 **final** 拼接为 Markdown / Word(.rtf)。

## 段落纪律

- **一段一职**：每段只做一件事（背景/空白/方法/结果/对比/机制/意义/局限之一）；
- **段落流动**：首句是主题句；其后每句与上一句有明确关系（因果/对比/限定/举例）；
- **动词校准**：show/demonstrate（强证据）、suggest/indicate（趋势级）、may/could（未验证机制）；
- **删除无据声明**：清除 first/unprecedented/revolutionary/comprehensive/always/never。

## 各节要点

- **引言**：漏斗式——大背景 → 领域现状 → 尚未解决的问题 → 本文贡献；
- **方法**：可复现（模型架构、超参数、损失函数公式、数据处理）；
- **结果**：突出「发现」，关键处给量化结果，图/表就近引用；
- **讨论**：突出「为什么重要」与「局限」，坦诚边界。

## 输出

- 只输出这一节的草稿，不写全文；
- 数据/文献缺失处用「[示例数据/待补文献]」占位，不编造；
- 附一句「本节一句话论证」，方便核对；
- 同步更新「写作」悬浮窗，用户可随时查看已写各节与台账，并一键导出全文 Markdown。
